Event Driven Architectures
What in your code triggers events (e.g., GUI, buttons, timeout ...)?

The system is built upon an asynchronous, decoupled event-driven architecture responding to user input, form submissions, and timers:

  • GUI Button & Click Events (addEventListener('click')): Clicking investigation buttons triggers room searches (investigateRoom(roomId)) to discover clues asynchronously; clicking suspect cards launches interrogation modals (interrogateSuspect(id)); clicking two clues on the Detective Evidence Board triggers deduction comparison routines (evaluateDeduction()); and clicking close buttons (.modal-close) or the overlay backdrop dismisses modals.
  • Form Submission Events (onsubmit): The cipher safe puzzle modal (#puzzle-form) intercepts submission via e.preventDefault(), triggering an asynchronous fetch() to validate code solutions against api/banana.php and provide real-time UI feedback without page reload.
  • Input Change Events (onchange): Selecting dialogue topics in the interrogation dropdown (#interrogate-dialogue-select) triggers dynamic updates to suspect testimony transcripts.
  • Keyboard Accessibility Events (keydown): A global keydown listener captures the Escape key to cleanly close active modals.
  • Asynchronous Timers & Timeouts: A 60-second client-side interval timer (setInterval) periodically queries api/auth.php?action=status to verify session validity; a 10-minute server-side inactivity timeout purges session state upon expiration; and setTimeout drives procedural typewriter audio intervals and alert toast animations.

Multi-Tier Interoperability Flow:
Client Browser (fetch / JSON) ↔ Local Application Server (api/banana.php cURL proxy) ↔ External Cloud Service (marcconrad.com/uob/banana/api.php).

It tracks latency telemetry via X-Banana-API-Latency-Ms headers and provides graceful JSON error fallback handling (HTTP 502/503).

Virtual Identity
How did you implement virtual identity in your code? (e.g., Passwords, Cookies, IP Numbers ...)

Virtual identity is implemented across credential security, session tracking, and persistent detective gameplay state:

  • User Credentials & Cryptographic Password Hashing: Detectives register and log in with unique accounts stored in the MySQL users table. Passwords are never stored in plaintext; they are securely salted and hashed using Bcrypt (PASSWORD_BCRYPT) via PHP's password_hash() and verified using timing-attack resistant password_verify() in api/auth.php.
  • Stateful Session Management & Cookie Hardening (PHPSESSID): Virtual identities are maintained through PHP session cookies (PHPSESSID) configured with security directives: HttpOnly (protecting cookies against XSS script access) and SameSite=Lax (mitigating cross-site request forgery).
  • Strict 10-Minute Inactivity Lifetime: Sessions are strictly limited to 600 seconds (10 minutes) via session.gc_maxlifetime = 600 and server-side activity timestamp tracking ($_SESSION['last_activity']). Exceeding 10 minutes purges session data and expires the cookie.
  • Persistent Relational State: The virtual identity maintains complete case progress across sessions: discovered clues, unlocked rooms, pinned evidence, safe status, and notes are saved in the game_sessions table linked by the user_id foreign key.
Any other interesting features:
  • Procedural 1940s Noir Audio Synthesizer (assets/js/audio.js): A zero-dependency procedural sound generator built entirely using the HTML5 Web Audio API with custom oscillators, biquad bandpass filters, and noise buffers to generate vintage mechanical typewriter clatter, warm vinyl crackle, minor-chord jazz ambient drones, and clue discovery stings without external audio files.
  • Interactive Deductive Evidence Board: A corkboard interface allowing detectives to pin and connect clue pairs. An inference engine validates paired evidence relationships to unlock breakthrough deductions and advance the investigation.
  • Branching Multi-Ending Narrative System: Dynamically calculates 3 distinct case outcomes based on detective performance: Master Detective (flawless evidence threshold + solved cipher safe + correct culprit), Compromised Solution (correct culprit accused with insufficient evidence), and Cold Case Dismissal (wrong suspect accused or attempts exhausted).
  • Self-Healing Database & Diagnostics Utility (database/healthcheck.php): Fault-tolerant database abstraction (config/db.php) featuring automatic port failover (ports 3306/3307), schema self-migration, and an enterprise diagnostic healthcheck endpoint verifying connectivity, table integrity, and record counts.
